# Shell Emulator

Эмулятор командной оболочки UNIX-подобной операционной системы на Python с графическим интерфейсом Tkinter.

Практическая работа по дисциплине «Конфигурационное управление», вариант №25. Реализованы этапы 1–4.

## Возможности

- Интерактивный ввод команд, разбор аргументов и сообщения об ошибках.
- Рабочие команды `ls`, `cd`, `pwd`, `du`, `history` и `exit`.
- Настройки запуска через аргументы командной строки и XML с приоритетом XML.
- Автоматическое выполнение стартовых скриптов с комментариями `#`.
- Загрузка VFS из CSV в память, включая вложенные каталоги и файлы с двоичным содержимым.
- Проверка ошибок CSV, путей, Base64 и наличия родительских каталогов.
- Создание минимальной VFS в памяти, если путь не указан.

Команды работают со словарём VFS в оперативной памяти. Текущий каталог и история команд сохраняются в течение сеанса. Для отладки при запуске отображается список элементов VFS.

## Требования и запуск

- Python 3.13 и стандартная библиотека Tkinter.
- Windows для запуска `.bat`-скриптов; дополнительные Python-библиотеки не нужны.

Из корня проекта:

```powershell
.\run.bat
.\run.bat --vfs examples/nested.csv
.\run.bat --script scripts/demo_stage3.txt
.\run.bat --config config.xml
```

Параметры `--vfs`, `--script` и `--config` необязательны. При отсутствии `--vfs` создаётся VFS по умолчанию, содержащая корневой каталог `/`.

## Конфигурация

Файл `config.xml` содержит пути к VFS и стартовому скрипту:

```xml
<config>
    <vfs>examples/sample.csv</vfs>
    <script>scripts/demo_stage4.txt</script>
</config>
```

Если один и тот же параметр задан и в XML, и в командной строке, значение из XML имеет приоритет. Пути определяются относительно текущей рабочей директории. Для корректной работы запускайте команды из корня проекта; демонстрационные `.bat`-скрипты переходят туда автоматически.

## Формат виртуальной файловой системы

CSV в кодировке UTF-8 имеет ровно три столбца в заданном порядке:

```csv
path,type,content
/,dir,
/home,dir,
/home/user,dir,
/home/user/hello.txt,file,SGVsbG8h
```

- `path` — абсолютный путь с `/`; корень `/` обязателен.
- `type` — `dir` (каталог) либо `file` (файл).
- `content` — содержимое файла в Base64; у каталогов поле пустое.
- Родительские каталоги должны присутствовать в CSV; дубликаты путей недопустимы.
- Содержимое файлов после декодирования хранится в Python как `bytes`.

Формат CSV разработан для этого проекта; методичка требует CSV, но не определяет названия столбцов. Исходные CSV открываются только для чтения и не изменяются.

Примеры файлов:

| Файл | Содержимое |
|---|---|
| `examples/minimal.csv` | Только корень `/` |
| `examples/files.csv` | Несколько файлов, включая двоичный |
| `examples/nested.csv` | Каталоги и файлы более чем на трёх уровнях |
| `examples/sample.csv` | VFS для `config.xml` |
| `examples/invalid.csv` | Ошибочный CSV для проверки обработки ошибок |

## Команды эмулятора

| Команда | Назначение |
|---|---|
| `ls [path]` | Показать непосредственное содержимое каталога или имя файла |
| `cd [path]` | Перейти в каталог; без аргументов — в `/` |
| `pwd` | Показать абсолютный путь текущего каталога |
| `du [path]` | Показать суммарный размер файла/каталога в байтах |
| `history` | Показать пронумерованную историю команд сеанса |
| `exit` | Закрыть окно эмулятора |

В `ls` и `du` отсутствие пути означает текущий каталог. Поддерживаются
абсолютные и относительные пути, включая `.` и `..`. В `du` у каталога
суммируются байты всех вложенных файлов (это упрощённое поведение, не
дисковые блоки UNIX). `history` включает текущую команду `history`,
а также команды с ошибками; пустой ввод не сохраняется. Команды
принимают не более одного пути, а `pwd`, `history`, `exit` не принимают
аргументов.

Неизвестные команды, неправильные аргументы и отсутствующие пути вызывают
сообщения об ошибках. Стартовый скрипт выполняет команды по одной строке,
пропускает пустые строки и комментарии `#`, отображает ввод и вывод.

Пример интерактивного сеанса (при загрузке `examples/sample.csv`):

```text
pwd
ls
cd /home/user
pwd
ls docs
du docs
cd ..
history
```

## Демонстрация

В `scripts/` находятся шесть демонстрационных Windows-скриптов:

- `01_default.bat` — запуск без параметров (VFS по умолчанию).
- `02_cli.bat` — параметры `--vfs` и `--script`, команды четвёртого этапа на `sample.csv`.
- `03_xml_override.bat` — приоритет XML над командной строкой.
- `04_vfs_minimal.bat` — минимальная VFS из CSV.
- `05_vfs_nested.bat` — вложенная VFS и команды четвёртого этапа.
- `06_vfs_errors.bat` — ошибки отсутствующего и некорректного CSV.

`demo_stage4.txt` проверяет команды навигации, размеры, историю и ошибки; `demo_stage3.txt` сохранён для демонстрации предыдущего этапа. После запуска отображаются прочитанные пути VFS. Ошибки загрузки VFS выдаются до открытия окна.

## Тестирование

Из корня проекта:

```powershell
py -m unittest discover -s tests -v
```

40 тестов проверяют загрузку и структуру VFS, работу команд, переходы между каталогами, размеры файлов и папок, историю, аргументы и обработку ошибок.
